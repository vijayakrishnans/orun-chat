# orun-chat-launch — design

## 1. The resource

Reused from the baseline unchanged, in the D1 database `cloudflare-d1` (one per environment):

```
users      the signed-in (GitHub) or guest owner of chats
chats      id, user_id, title, created_at
messages   id, chat_id, role, parts (JSON), created_at
```

Uploads are objects in the R2 bucket `cloudflare-r2`, keyed by owner. Nothing is new.

## 2. The API

The template's Nitro routes in the `web` Worker, unchanged:

```
POST   /api/chats            create a chat
GET    /api/chats            list the caller's chats
GET    /api/chats/{id}       one chat with its messages
POST   /api/chats/{id}       send a message; streams the reply (Workers AI)
DELETE /api/chats/{id}       delete a chat
POST   /api/upload           store an attachment in R2
```

A caller only ever sees their own chats.

## 3. The surface

The Nuxt UI chat: a new-chat page, the chat view with streaming replies, the history sidebar, and a sign-in button that becomes live when the GitHub OAuth app is set. From OC2 the page background is a chessboard: cream and brown alternating squares (a CSS conic gradient on `body` in `apps/web/app/assets/css/main.css`), one pair for light mode and one for dark.

## 4. Events, secrets, and integrations

Cloudflare only. Brokered secrets `CLOUDFLARE_API_TOKEN` (workers-deploy), `CLOUDFLARE_R2_TOKEN` (r2-data) and the D1 root's token are minted by the build. Workers AI is the Worker's own binding. The session key is generated by a migration.

## 5. Out of scope

A custom persona, answering from documents (RAG), an embeddable widget, a custom domain, and the AI Gateway models. Each is a later epic.
